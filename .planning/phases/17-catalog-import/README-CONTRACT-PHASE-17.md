## Найдено и исправлено в этой фазе

**Кириллический LIKE в SQLite** (`app/database.py`): LIKE фолдит регистр
только для ASCII — запрос «поилка» не находил «Поилки групповые» (заглавная П
в начале названия). Fix: UDF `u_lower` (Python str.lower) регистрируется на
connect; поиск в каталоге использует `u_lower(name) LIKE %q.lower()%`.
До фикса «поилка» → 30 результатов, после — 51 (и «ПОИЛКА» → 51).

## Design decisions

1. **Картинки в `storage/catalog/images/`, не в `app/static/`** — app/static
   запекается в образ (COPY) и не является volume; runtime-файлы там не
   переживут пересоздание контейнера. Отдача — файловым роутом
   `/catalog/images/{file}` (basename-guard), который NOT в EXEMPT_PATHS →
   требует сессию через AuthMiddleware. Публичного mount у storage/ нет.
2. **`source_url` — upsert-ключ** (в каталоге АгроВиты уникален — проверено по
   1355 строкам). Для следующих поставщиков с неуникальными URL — составной
   ключ (brand + url) расширением скрипта, модель менять не надо.
3. **image_file хранит только имя файла** — URL строится роутом; полный
   URL источника картинки не хранится в БД (восстанавливается из xlsx при
   докачке `--images-only`).
4. **Категории импорта — корневые узлы**: в файле подкатегория дублирует
   категорию; дерево self-FK готово к следующим поставщикам с глубиной.
5. **PER_PAGE=48** (сетка 4 колонки × 12 рядов), пагинация prev/next через HTMX.

## Известные ограничения

1. Счётчик категорий в сайдбаре считает только активные товары прямого
   вхождения + потомков; товары без категории (category_id NULL) не видны
   в дереве — в импорте АгроВиты их нет (все 1355 имеют категорию).
2. Поиск не ищет по морфологии («поилк**а**» найдёт «поилки» только подстрокой).
   Для каталога 1-2k SKU достаточно; полнотекст — по потребности.
3. Gate-автоматизации нет — верификация ручная (TestClient + IAB), как и в фазе 16.

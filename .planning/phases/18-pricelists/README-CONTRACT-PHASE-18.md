## Design decisions

1. **PriceList создаётся лениво и только при появлении первой цены** — пустой
   «Базовый» не мусорит UI (ни импорт, ни ручное сохранение не создают пустой список:
   ручное сохранение создаёт список при апсерте первой валидной цены — приемлемо).
2. **min_qty в модели, не в UI** — заложен под ступенчатые скидки, v2.0 не используется.
3. **Пустое поле в форме = «не трогать»** (не «очистить цену») — безопасно при
   выборочной правке; очистка цены — осознанная операция, сейчас не нужна.
4. **Парсинг цен** (`parse_price_amount`): пробелы/nbsp-разделители, запятая→точка,
   заглушки («уточняйте») → None; ≤0 → None. Живёт в `catalog_service`, общий
   для скрипта и роутов.
5. **`catalog_service.py` вынесен** — единый upsert-слой для скрипта и роутов
   (правило зависимостей: скрипт импорта и /prices/import используют одни функции).

## Известные ограничения

1. Массовое сохранение действует на видимые 100 строк страницы — правки в нескольких
   категориях требуют нескольких сохранений. Принято (правка обычно внутри категории).
2. Артикулы поставщика неуникальны — find_product берёт первый активный по sku;
   приоритет у поиска по source_url (надёжный).
3. Валюты: поле в модели есть, пересчёта BYN/EUR нет (ждём реальные прайсы поставщика,
   решение за владельцем).

## Design decisions

1. **Снапшот цены — из формы менеджера, снапшот name/sku/unit — строго из БД.**
   Менеджер может править цену строки (билдер подтягивает прайс, но не блокирует);
   описание товара подменить нельзя. Сервер пересчитывает суммы по Decimal.
2. **Нумерация** — SequenceCounter(name,year) c flush; формат КП-2026-0001
   (переиспользуется для счетов в фазе 20 — prefix «СЧ»).
3. **Стадии двигаются только вперёд и только по числовым стадиям** (`stage.isdigit()`
   и меньше целевой); ValueError воронки не валят статус КП (отправка КП не может
   упасть из-за валидации стадии).
4. **Правка черновика = полная замена позиций** (bulk delete + insert) — проще и
   надёжнее частичных правок; аналогично_behaviorу Odoo-цитат.
5. **Печатная форма** — отдельный standalone-шаблон (print/quote.html) без base.html:
   WeasyPrint не исполняет JS, Tailwind-CDN мёртв для него; DejaVu Sans/Mono из
   fonts-dejavu-core. Реквизиты продавца и НДС-блок — фаза 20 (CompanyProfile).
6. **КП создаются любым авторизованным** (как карточка лида); отдельный ACL на КП не
   вводили — гранулярных пермишенов в CRM нет (3 роли, líder общий доступ).

## Известные ограничения

1. Пагинации/поиска в табе «КП» карточки лида нет — список короткий (несколько КП на лид).
2. Валидная дата (valid_until) не блокирует ничего автоматически — только бейдж
   «Просрочено» на sent-КП; авто-expiry (cron) — по потребности.
3. PDF локально на Windows недоступен (нет GTK) — осознанно, верификация в контейнере.
4. Таб «КП» в lead_card грузится всегда (не лениво) — объём мал, ок.
